2章 AIでデザイン情報を"丸ごと"スキャン

この章の目安学習時間：2時間

この章で到達できるゴール：

  • SVGとJPG/PNGの特性を理解し、デザインカンプの形式に応じて適切な情報抽出方法を選択できる。
  • SVGファイルの中身を読み解き、テキストがアウトライン化されているかなどの状態を判断できる。
  • テキスト情報が保持されたSVGからは、AIで正確なスタイル情報を抽出し、それ以外の場合はJPG/PNGと同様のアプローチで賢く推測できる。

【2-1】はじめに：デザインカンプの形式を確認しよう

目安の学習時間：10分

SVG vs JPG/PNG：あなたに渡されるデータはどっち？

Web制作の実務では、クライアントやデザイナーから様々な形式でデザインデータが提供されます。
特に代表的なのが、SVG（ベクター形式）とJPG/PNG（ラスター形式）です。
この2つは根本的に構造が異なるため、AIで情報を抽出する際のアプローチも変わってきます。

まずは、それぞれの特徴を理解しましょう。
項目
SVG (ベクター形式)
JPG/PNG (ラスター形式)
データの正体
点や線の座標、色などを数値で記録したコード
ピクセルという色のついた点の集合体
特徴
拡大・縮小しても画質が劣化しない
拡大すると画像が荒くなることがある
主な用途
ロゴ、アイコンなど、シャープさが求められる図形
写真、複雑なイラスト、Webサイト全体のデザインカンプ
情報抽出
コードを「解析」して正確な値を取得可能
画像を見て「推測」する必要がある
実務では、「ロゴはSVG、サイト全体のデザインカンプはJPGで」というように、複数の形式が混在して提供されることも少なくありません。

形式と"中身"によって戦略を変える！

このような特徴の違いから、AIに情報を抽出させる際の戦略を立てる必要があります。
  • 理想的なSVGの場合：
    AIの頭脳（コード解析能力）を使い、書かれているコードを解析させ、「正確な答え」を引き出します。
  • JPG/PNGや"訳あり"SVGの場合：
    AIの眼（画像認識能力）を使い、描かれている内容を認識させ、「賢い推測」を引き出します。
この章では、この2つのアプローチを両方学び、どのような状況にも対応できるスキルを身につけていきます。

【2-2】ケース1：SVGから"正確な"情報を抜き出す方法（と、その限界）

目安の学習時間：40分

SVGファイルの中身を覗いてみよう

SVGファイルは、その実体は画像データではなく、XML（eXtensible Markup Language）というマークアップ言語で記述されたテキストファイルです。
つまり、HTMLのようにタグで構造が定義されています。
そのため、テキストエディタ（Visual Studio Codeなど）でファイルを開くことで、その中身を直接確認できます。

コードの中には、図形の形を定義する<path>タグ、色を指定するfill属性、テキストを記述する<text>タグなどが含まれています。この構造をAIに読み解かせることで、正確な情報を引き出します。
VS CodeでSVGのコードを表示する手順

VS Codeの拡張機能により、SVGが自動で画像として表示されることがあります。その場合、以下の手順でコード表示に切り替えられます。

  1. 画面上部のファイル名が書かれたタブを右クリックします。
  2. 表示されたメニューから「Reopen Editor With...」を選択します。
  3. 次の選択肢で「Text Editor」を選びます。

注意！SVGでも情報が取れない"訳あり"ケース

SVGはコードベースであるため正確な情報を得やすい形式ですが、万能ではありません。
実務では、SVGファイルからでも直接情報を読み取れない「訳あり」ケースが存在します。
注意

SVGファイルを受け取ったからといって、必ずしも全ての情報がコードから読み取れるとは限りません。以下の2つのケースには特に注意が必要です。

  • ケースA：テキストが「アウトライン化」されている
  • ケースB：SVG内に「画像が埋め込まれている」
ケースA：テキストが「アウトライン化」されている
アウトライン化とは、フォント情報を持つ「文字」を、形だけのデータである「図形（パス）」に変換する処理です。
これにより、どの環境でファイルを開いても同じ見た目を保てますが、元々のフォント名やサイズといったテキスト情報は失われます。
ケースB：SVG内に「画像が埋め込まれている」
SVGファイルの中に、`<image>`タグを使ってJPGやPNGなどの画像（ラスター画像）を埋め込むこともできます。この場合、SVGは画像の「額縁」の役割しか果たしておらず、SVGコード自体には、埋め込まれた画像の色やフォントの情報は含まれていません。
これらの"訳あり"SVGの対応策
これらのケースでは、SVGであってもコード解析は有効ではありません。
そのため、次のセクションで学ぶJPG/PNGと同じアプローチ、つまりAIの画像認識能力を使って「推測」する方法で攻略します。

AIに"理想的な"SVGコードを解析させる方法

テキスト情報が保持されている、いわば「理想的な」SVGファイルであれば、AIのコード解析能力を最大限に活用できます。
最も確実な方法は、SVGファイルのコードを全てコピーし、AIのプロンプトに貼り付けて解析を依頼することです。
応用事項：長いコードを分割して送信する方法

万が一、SVGコードがAIの入力文字数制限を超えるほど長い場合の代替案です。

  1. まず、「これから非常に長いSVGコードを複数に分けて送信します。全てのパーツを送り終えたら合図するので、それから全体を解析してください。」のように、AIに事前通告します。
  2. コードを複数に分割し、「SVG Part 1/3」のようなヘッダーを付けて、順番に送信します。
  3. 最後のパーツを送り終えたら、「全てのパーツを送信しました。解析を開始してください。」と指示します。

この方法は手間がかかりますが、非常に複雑なSVGファイルを扱う際に役立つことがあります。

この方法を使えば、テキスト情報が残っているSVGからは、1pxの狂いもない正確な情報を手に入れることができます。

AIの「眼」で画像をスキャンする基本

次に、JPG/PNGのようなラスター画像や、先ほど学んだ「訳あり」SVGから情報を抽出する方法です。
こちらでは、AIの画像認識能力を活用します。
このアプローチは、コードを読むのではなく、人間が絵を見るのと同じように、画像に何が描かれているかをAIに「見せて」判断させます。
サイト全体のデザインカンプ画像や、特定のコンポーネントだけを切り取ったスクリーンショットをAIにアップロードして、対話を開始します。

それぞれのHEXコードを教えてください。

色・フォント・余白を"推測"させるプロンプト術

画像認識は非常に強力ですが、AIが提供する情報はあくまで「推測」であるという点を理解しておくことが重要です。
ミリ単位の正確さではなく、実装の指針となるおおよその値を得ることを目的とします。

以下に、部位ごとのプロンプト例を示します。
  • 色を抽出したい場合：
    このWebサイト画像で使われている主要な色とアクセントカラーを推測し、それぞれのHEXコードを教えてください。
  • フォント情報を知りたい場合：
    この画像の見出しと本文のテキストについて、フォントサイズとフォントの太さ（font-weight）を推測してください。
  • 余白やレイアウトを知りたい場合：
    このカードコンポーネントの内部の余白(padding)と、角の丸み(border-radius)の値をピクセル単位で推測してください。
重要：推測値の扱い方
  • AIが提示した値は、絶対的な正解ではありません。
  • 例えば、AIが余白を「23px」と回答した場合、デザインの意図はキリの良い「24px」である可能性が高いです。
  • このように、AIの回答を鵜呑みにせず、デザインの原則（8の倍数ルールなど）に照らし合わせて人間が最終判断を下すことが、品質を高める上で非常に重要です。この「判断力」こそが、AI時代に求められるスキルです。

【2-4】章末課題 - AIの「眼」でデザイン意図を読み解こう！

目安の学習時間： 15分

問題

あなたはWeb制作の途中、デザイナーから「急ぎなので、まずはこの画像のデザインでボタンを実装しておいてください！」と、以下の画像ファイルだけを受け取りました。

このボタンを実装するために、まずはAIの画像認識能力を使って必要なCSSの値を推測し、最終的なコードを完成させましょう。

使用素材（button_design.png）

解答手順

STEP 1: ボタンの画像を用意する
上の青い「詳しくはこちら」ボタンのスクリーンショットを撮り、`button_design.png`などのファイル名でPCに保存します。

STEP 2: AIに画像をアップロードしてCSSの値を推測させる
保存したボタンの画像をAIにアップロードし、実装に必要な値を包括的に質問します。

プロンプト例：
このボタンの画像から、以下のCSSプロパティの値を推測してください。
  • 背景色 (background-color)
  • 文字色 (color)
  • 角の丸み (border-radius)
  • 内側の余白 (padding)
  • フォントサイズ (font-size)
STEP 3: AIの回答を元に最終的なCSSを記述する
AIはあくまで「推測」した値を返します。（例：`padding`が「11px 23px」など）
その回答を元に、「キリの良い数字にしよう」「デザインの原則（4や8の倍数）に合わせよう」といったあなた自身の判断を加えて、最終的なCSSコードを完成させてください。

STEP 4: 「判断」の理由を説明する
なぜそのCSSの値にしたのか、あなたの判断の根拠を記述してください。
この「なぜそうしたか」を言語化する癖をつけることが、スキルアップの鍵となります。

解答例

AIからの回答（推測値の例）
  • 背景色: #007BFF
  • 文字色: #FFFFFF
  • 角の丸み: 7px
  • 内側の余白: 11px 23px
  • フォントサイズ: 15.5px
あなたの最終判断とCSSコード
.button {
  /* 色はAIの推測が正確そうなのでそのまま採用 */
  background-color: #007BFF;
  color: #FFFFFF;

  /* AIの推測値「7px」を、キリの良い「8px」に修正 */
  border-radius: 8px;

  /* AIの推測値「11px 23px」を、デザイン原則（4の倍数）を意識して「12px 24px」に修正 */
  padding: 12px 24px;

  /* AIの推測値「15.5px」を、標準的な「16px」に修正 */
  font-size: 16px;

  /* その他のスタイル */
  font-weight: bold;
  text-decoration: none;
  display: inline-block;
}
CSS
判断理由の記述例
AIが推測した値は、角の丸みが7px、余白が11px 23pxなど、少し不規則な数値でした。
Webデザインでは4や8の倍数で数値を設計することが多いため、デザイナーの意図は最も近いキリの良い数値だと判断しました。
そのため、角の丸みは8px、余白は12px 24px、フォントサイズは16pxにそれぞれ修正しました。
お疲れ様でした！
