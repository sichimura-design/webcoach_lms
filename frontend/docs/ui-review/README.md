# UI/UX レビュー台帳

細部の UI/UX 改善を、重複なく・再発なく回すための台帳一式。
**レビュアーは最初にこのファイルを読んでください。**

作成 2026-08-06 / 移設・改訂 2026-08-27（`docs/` は git 追跡外だったため、ここへ移設）

## 1. まず知っておくこと — 指摘は3つに分類する

記録するとき、**分類**列に `A` / `B` / `C` を必ず入れてください。**分類ごとに直し方が違います。**

| 分類 | 中身 | 直し方 |
|---|---|---|
| **A: 横断** | 色・余白・文字サイズのばらつき、ボタン／カードの実装差、モーダルの閉じ方、空・読み込み・エラー表示の欠落、用語のばらつき | **画面ごとに直さない。** トークン／共通部品／規約を1箇所直す |
| **B: 画面固有** | 情報設計、その画面の文言、導線、そこにしかない違和感 | 画面ごとに直す |
| **C: 教材語彙** | 移行教材（Clipkit由来）の本文の見た目 | HTML の class 単位で直す（1つ直すと全レッスンに効く） |

**迷ったら「他の画面でも同じことが起きているか」を1つだけ確認してください。** 起きていれば A です。

なぜ分けるのか: A を画面ごとのレビューで拾うと、**同じ指摘が画面数ぶん重複して出て、修正も画面数ぶん発生します**。
実際にこのリポジトリでは「余白 → 文字サイズ → KPIのはみ出し」と同種の崩れを直すコミットが連続しており、
1画面ずつ直しても再発しています。A は規約と共通部品の側で1回直すのが正しい。

## 2. 実施順 — 1〜4日目は「横串」

**観点を1つ固定して、複数画面を横に並べて比べる**日を先に置いています（フェーズ5 / `CONSISTENCY-*`）。
ばらつきは横に並べた瞬間に見えるので、A分類がまとめて・重複なく出ます。

| 日 | 観点 | タスク |
|---|---|---|
| 1 | ボタンと現在地 | `CONSISTENCY-001`, `CONSISTENCY-002` |
| 2 | カード・空状態・モーダル・トースト | `CONSISTENCY-003`, `CONSISTENCY-005` |
| 3 | 色・余白・アイコンと、言葉の統一 | `CONSISTENCY-006`, `CONSISTENCY-004` |
| 4 | アカウント導線と、PC幅の許容範囲 | `CONSISTENCY-007`, `DEVICE-005` |
| 5日目以降 | 画面ごと・状態ごと・端末ごと | `FLOW-*` → `SCREEN-*` → `STATE-*` → `DEVICE-*` |

5日目以降で1〜4日目と同じことに気づいたら、**書かずに「1日目で既出」と備考に入れて進んでください。**

## 3. 確認する画面幅は3つに固定

| 幅 | 位置づけ |
|---|---|
| **1920px** | 等倍。デザインの基準幅（1900px）に最も近い |
| **1520px** | **最も崩れる幅。飛ばさないこと。** Windows の表示倍率125%で CSS 上の可視幅がここまで落ちるため、実利用環境の多数がこの幅に当たる（根拠は `frontend/src/index.css` の可変スケール節のコメント） |
| **390px** | スマホ |

トークンと共通部品を**1画面に横並びで**出す開発用ページを追加しました。
**1〜3日目（ボタン・カード・色・余白）は、まずここを見てから実画面に行くと早いです。**

- 実装は `frontend/src/components/dev/DevCatalogPage.tsx`。
  **部品を追加・変更したらここにも並べてください。** 最新でないと横串レビューが空振りします。

### この画面で最初に見えること（＝1日目の指摘候補）

`ui/button` の "brand" 系 variant は**すべて旧ピンク／アンバー**を指しています
（`brand.DEFAULT` = `#FF5A7A`、`brand-gradient` = アンバー→ピンク、shadcn `--primary` =
`hsl(348 100% 68%)`）。統一済みのブランド赤 `#D60934` は別系統の `dash.*` にあります。
**つまり `ui/button` を使うと旧ピンクが出るため、新しい画面は共通部品を使えず生 `<button>` に戻っています**
（生 `<button>` は全体で322箇所）。共通部品へ寄せるより先に `tailwind.config.js` と
`index.css` の `--primary` を直す必要がある、という順序がここで決まります。

## 7. 画面台帳（`screen-inventory.csv`）の読み方

列は2種類に分かれています。

- **機械で埋めた列**（`ファイル数` 〜 `状態表示`）… コードを走査した結果。**目安です。**
  特に `状態表示` は文字列一致による推定なので、実際に表示されるかは目視で確認してください。
- **人が埋める列**（`優先度` `レビュー担当` `実施日` `指摘数` `ステータス` `メモ`）… 空です。運用で埋めます。

画面IDの接頭辞: `PUB`=公開 / `STU`=受講者 / `SHELL`=全画面共通 / `LEG`=レガシー / `ADM`=管理者 / `CCH`=コーチ。

### 現時点で台帳から読み取れること

1. **トークンは系統が混在している。** 2系統以上を併用している画面が7つ。うち5つ（`/mypage` `/study-log`
   `/notes` `/coaching` `/ai-coach`）は `--dc-*`（最新）と `webcoachTheme`（現最大勢力）の併存。
   `tokens.ts` は `/courses` だけ、`MUI` はレガシー3画面だけ、`Tailwind brand.*` は管理画面とログインに残存。
2. **`ui/*` の共通部品がほぼ使われていない。** 受講者向け14画面のうち採用は `/mypage` だけ。
   代わりに生 `<button>` が `/coaching` に56、`/course/:id` に41、`/ai-coach` に28、`/notes` に26。
   **押す場所の見た目を揃えたいなら、画面を直すより先に共通部品へ寄せる必要がある**（A分類）。
3. **レスポンシブ方式が3系統。** 主力は `clamp(--dc-*経由)`。`transform:scale`（旧方式）は `/courses` の1画面だけに縮小済み。
   一方 **`/learning-plan`・`/learning-plan/setup`・`/connect/:token` は幅対応が入っていない**（`（固定）`）。
4. **生hex（`#RRGGBB` 直書き）は管理画面に集中。** `coach-mapping` 55 / `coach-integrations` 52 / `students` 35。
   受講者向けの主要画面は概ねトークン参照へ移行済みなので、**管理画面と受講者画面は優先度を分けて扱える。**
5. **到達導線が切れている画面がある。** `/study-log`（サイドバーに無い）、`/learning-plan`（参照元
   `mypage/RoadmapStrip.tsx` はどこからも import されていない死んだ部品）、`/profile`、`/badges`。
   **レビュー前に導線を繋ぐか、直URLで開く前提を決めてください。**
6. **レガシー4画面＋到達不能1画面（計2,286行）はレビュー対象外にできる。**
   `LEG-01`〜`LEG-05`。削除するか凍結するかを決めると、レビュー母数が32→27画面に減ります。

## 9. UI を直したらヘルプ本文も直す

**`frontend/src/components/help/HelpPage.tsx` の `MANUAL_SECTIONS` / `FAQ_ITEMS` は、画面の作り替えに
追随していません。** 2026-08-27 時点で現行 UI と 10 箇所以上ずれています（廃止済みの「集中ブース」が1節
まるごと残っている、レッスンの「左の目次」を説明している、など。一覧は
[`findings-2026-08-27-claude.md`](findings-2026-08-27-claude.md) の `CL-B62`）。

ヘルプは外部 Notion ではなく LMS 内の定数なので、**直し忘れるとユーザーが存在しない画面を探すことになります。**
画面の文言・導線・機能を変える修正では、同じ PR の中で次を確認してください。

- 変えた画面が `MANUAL_SECTIONS` のどの節に書かれているか
- 変えたボタンの文言が `FAQ_ITEMS` に引用されていないか
- 機能を廃止したら、その節ごと消えているか
