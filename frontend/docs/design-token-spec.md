# デザイン出力フォーマット仕様（Claude design / ChatGPT 向け）

## これは何か

`webcoach_lms` フロントのモック画面（マイページ・学習コンテンツ・コーストップ・レッスン・集中ブース・AIサポート）は、以下のような流れで実装してきた。

1. デザインツール（ChatGPT Image、Claude design など）でビジュアルを作る
2. それを画像またはHTMLコンプとして受け取る
3. Claude Code がその見た目を読み取り、Reactコンポーネントのインラインstyleとして移植する

このとき、**入力が「見た目の画像」だと移植のたびに色・角丸・余白の具体値がブレる**（人間が画像を見て見積もるのと同じ理由）。一方、`design_handoff_lms_app/WebcoachApp.dc.html` のように**リテラルな数値がそのまま書かれたHTML**を渡された回は、ズレがほぼ発生しなかった。

この仕様は、今後デザインツールに出力してもらう際に「ズレない形式」を指定するためのもの。実際に使われている値は `frontend/src/theme/tokens.ts` に集約してあるので、今後の新規デザインもそこから外れないようにしたい。

## 実装上の既存ルール（デザイン出力にも反映してほしい制約）

- **他の学習者は必ず仮名＋絵文字アイコン**。実名・実写真は絶対に出さない（デザイン案の中に実名サンプルが入っていても、実装時はダミーの仮名に置き換える前提）。
- **理解度%などの学習効果を数値化した指標は表示しない**（データモデルが無いため）。
- スタイリングは基本**インラインstyle直書き**（Tailwindは`flex`/`grid`など構造目的のみ）。デザイン出力もこの粒度（px・hexのリテラル値）で受け取れる形が望ましい。
- モバイル時にサイドバイサイドのグリッドが1カラムに落ちる設計を必ず含める（過去、これが漏れて崩れた実績あり）。

## Claude design / ChatGPT への依頼プロンプト（コピペ用テンプレート）

```
webcoach_lms というLMSモックの「{{画面名}}」画面をデザインしてください。
出力は画像だけでなく、以下の形式でも必ず出してください（Claude Codeが数値を推測せずそのまま実装に移すため）：

1. 全体レイアウトの構造（グリッド/フレックスの列数・比率、要素の親子関係）を文章で
2. 各要素の実測値を以下の粒度で列挙：
   - 色: hexコード（例: background: #E0213A）。曖昧な色名（「明るい赤」等）は禁止
   - 角丸: px（例: border-radius: 20px）
   - シャドウ: 完全なCSS box-shadow文字列（例: 0 10px 30px rgba(190,60,70,.08)）
   - 余白: padding/gapをpx単位で個別に
   - フォントサイズ・weight: px単位＋数値weight
   - グラデーション: 角度＋色2点をhexで

可能な限り、以下の既存トークンをそのまま使ってください（新しい値が必要な場合のみ新規に定義し、その理由を明記）：
- ブランドレッド: #E0213A / グラデーション明側 #F0546A
- カードのシャドウ: 0 10px 30px rgba(190,60,70,.08)
- カード角丸: 20px（大きめカードは22px）
- 補足テキスト色: #B78F98
- ボタンのグラデーション: linear-gradient(120deg,#F0546A,#E0213A)

他の学習者を表示する場合は必ず仮名＋絵文字アイコンにしてください（実名・実写真は不可）。
```

## Claude Code側の受け取り方

上記フォーマットで出力を受け取ったら、Claude Codeは画像を目で見積もるのではなく、**列挙された数値をそのままReactのstyleオブジェクトに転記する**。既存トークンと一致する値は `frontend/src/theme/tokens.ts` の定数を参照し、新しい値は他画面と一貫性があるか確認してから採用する。
